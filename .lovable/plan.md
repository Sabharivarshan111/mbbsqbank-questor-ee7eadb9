# Fix Google Sign-In 403: disallowed_useragent

## Root cause

Google blocks OAuth flows inside embedded WebViews (Android `WebView` used by Capacitor). Your APK opens `accounts.google.com` inside the in-app WebView, which triggers **Error 403: disallowed_useragent** ("Use secure browsers" policy). This is a Google policy — it cannot be bypassed by changing redirect URLs or Supabase settings. The fix is to open the OAuth flow in the **system browser** (Chrome Custom Tabs) instead of the WebView.

Note: the same code works fine on web/preview — this only breaks inside the Android APK.

## Fix

Use Capacitor's `@capacitor/browser` to open the Supabase OAuth URL in an external Chrome Custom Tab, then handle the redirect back into the app via a deep link.

### 1. Install plugins
- `@capacitor/browser` — opens system browser
- `@capacitor/app` — listens for deep-link return (`appUrlOpen`)

### 2. Configure deep link
- In `capacitor.config.ts`, add a custom scheme (e.g. `app.lovable.orbitmbbs://`) under `server` / `App` URL handling.
- In `AndroidManifest.xml` (auto-generated by Capacitor sync), the intent filter for this scheme will route the OAuth callback back into the app.
- In Supabase Dashboard → Authentication → URL Configuration → **Redirect URLs**, add:
  - `app.lovable.orbitmbbs://auth/callback`
  - Keep existing web origin too (so web/preview keeps working).

### 3. Update `GoogleSyncButton.tsx` / auth flow
Detect Capacitor native runtime via `Capacitor.isNativePlatform()`:
- **Web (preview/published site)**: keep current behavior (`linkIdentity` / `signInWithOAuth` with `redirectTo: window.location.origin`) — works fine in normal browsers.
- **Native (APK)**:
  1. Call `supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: 'app.lovable.orbitmbbs://auth/callback', skipBrowserRedirect: true } })` to get the auth URL without auto-redirecting the WebView.
  2. Open that URL with `Browser.open({ url })` — this launches Chrome Custom Tabs, which Google **does** allow.
  3. Listen with `App.addListener('appUrlOpen', ...)` for the callback deep link, extract the `code` / tokens from the URL hash/query, and call `supabase.auth.exchangeCodeForSession(code)` (or `setSession` for implicit flow) to complete sign-in inside the app.
  4. Close the browser tab with `Browser.close()`.

### 4. Preserve anonymous progress on native
Since `linkIdentity` requires the same session context, and native flow uses `signInWithOAuth`, anonymous→Google linking on native will be handled by: capturing the anonymous `user.id` first, then after Google sign-in, calling an edge function (or RPC) to migrate `profiles` / `question_progress` rows from old id to new id. (Out of scope if you only want sign-in to work — confirm if you want progress migration too.)

## Files

**Edit**
- `src/components/progress/GoogleSyncButton.tsx` — branch on `Capacitor.isNativePlatform()`, use Browser plugin path for native.
- `capacitor.config.ts` — add custom URL scheme.
- `src/main.tsx` (or new `src/lib/native-auth.ts`) — register one-time `App.addListener('appUrlOpen')` to exchange code → session.

**Install**
- `@capacitor/browser`
- `@capacitor/app` (likely already present)

**Manual (you do these once)**
- Supabase Dashboard → Auth → URL Configuration: add `app.lovable.orbitmbbs://auth/callback` to Redirect URLs.
- Google Cloud Console → OAuth client: no change needed (callback still goes to Supabase's `https://<project>.supabase.co/auth/v1/callback`, then Supabase 302s to your custom scheme).
- Rebuild APK: `npx cap sync android` → rebuild in Android Studio.

## Out of scope
- Changing Supabase project, OAuth client, or essay/short-notes code.
- Progress-migration RPC (ask if you want it included).

## Quick alternative (if you don't want native fix now)
Tell users to sign in via the **published web URL** (`https://mbbsqbank-questor.lovable.app`) in Chrome, then progress syncs to the same Supabase backend. The APK can stay anonymous-only.
